2KR PERF/PSEUDO
================

Contenu du dossier
- index.html    le site complet (accès, scan de pseudos, résultats, performance, connexion)
- manifest.json, sw.js, icon.svg   pour l'installer comme une app

Utilisation sur PC
1. Décompresse le .zip.
2. Double-clique sur index.html (s'ouvre dans ton navigateur).

Installer comme une app (PC et téléphone)
Il faut que le site soit en ligne en https (GitHub Pages, Netlify, Cloudflare Pages...).
Dépose le contenu du dossier, puis :
- PC (Chrome/Edge) : icône « Installer » dans la barre d'adresse.
- Téléphone : menu du navigateur > « Ajouter à l'écran d'accueil ».

Vérification des pseudos
Onglet « Connexion » (ou en bas de « Résultats ») : deux méthodes.
- Directe : le site interroge Discord (ou GitHub) depuis ton navigateur.
  Si le navigateur bloque la requête (CORS), passe par ton serveur.
- Mon serveur : colle l'URL de ton serveur. Il reçoit ?u=pseudo&p=plateforme
  et répond {"available":true} ou {"available":false}.
  Ce n'est PAS un lien d'invitation Discord (discord.gg/...).

Déployer le serveur (gratuit)
1. Compte Cloudflare > Workers & Pages > Create Worker.
2. Colle le contenu de worker.js, puis Deploy.
3. Copie l'URL https://xxx.workers.dev et colle-la dans « Mon serveur ».
4. Clique sur « Tester la connexion ».

Discord limite le nombre de vérifications : le site met le scan en pause
automatiquement quand la limite est atteinte. Garde la vitesse Normale ou Lente.

Se connecter avec un compte (onglet Connexion)
-----------------------------------------------
- Discord : fonctionne déjà, aucun serveur requis. Dans l'onglet Admin, colle le
  Client ID de ton appli Discord (Developer Portal > ton appli > OAuth2 > General).
  Ajoute ensuite l'adresse de ta page (celle affichée dans l'onglet Admin, sous
  "À ajouter dans Discord > OAuth2 > Redirects") dans OAuth2 > Redirects de Discord.

- Telegram : aucun serveur requis non plus.
  1. Ouvre une conversation avec @BotFather sur Telegram, envoie /newbot (ou utilise
     un bot existant), note son pseudo (sans le @).
  2. Toujours avec @BotFather : /setdomain, choisis ton bot, puis colle le nom de
     domaine de ta page (sans https://, juste le domaine, ex: tonsite.github.io).
  3. Dans l'onglet Admin du site, colle le pseudo du bot. Le bouton "Se connecter
     avec Telegram" apparaît dans l'onglet Connexion.

- GitHub, Twitter / X, Roblox : nécessitent ton serveur (worker.js), car ces
  plateformes exigent une clé secrète qu'on ne peut jamais mettre dans le site
  lui-même (n'importe qui pourrait l'y lire et s'en servir).
  Pour chacune :
  1. Crée une application OAuth sur la plateforme :
     - GitHub : github.com/settings/developers > OAuth Apps > New OAuth App.
     - Twitter / X : developer.twitter.com > ton projet > app Keys and tokens,
       active "OAuth 2.0" (type d'app : confidentiel / Web App).
     - Roblox : create.roblox.com/credentials > OAuth 2.0 > Create app.
  2. Renseigne la Redirect URI EXACTEMENT comme l'onglet Admin du site te
     l'indique (une fois « Mon serveur » rempli) : elle se termine par
     /oauth/github/callback, /oauth/twitter/callback ou /oauth/roblox/callback.
  3. Récupère le Client ID (public) et le Client Secret (jamais public).
  4. Dans Cloudflare : ton Worker > Settings > Variables and Secrets, ajoute :
     GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET,
     TWITTER_CLIENT_ID, TWITTER_CLIENT_SECRET,
     ROBLOX_CLIENT_ID, ROBLOX_CLIENT_SECRET
     (encrypt les deux "_SECRET"). Redeploy le Worker après les avoir ajoutées.
  5. Dans l'onglet Admin du site, colle les mêmes Client ID (ils doivent être
     identiques à ceux mis dans Cloudflare — le Client Secret, lui, ne se met
     jamais dans le site).

- Instagram et TikTok ne sont pas proposés : ces deux plateformes exigent que
  Meta ou TikTok examinent et valident ton application avant qu'elle fonctionne
  réellement pour d'autres personnes que toi, ce qui peut prendre plusieurs
  jours à plusieurs semaines. Demande leur validation si tu veux les ajouter
  plus tard.

Nouvelles fonctionnalités
-------------------------
- Thème clair/sombre : bouton en bas du menu de gauche, mémorisé sur l'appareil.
- Recherche d'un pseudo précis sur toutes les plateformes (onglet Scan) : montre
  où il est pris, avec les infos publiques disponibles (abonnés, dépôts) pour
  GitHub et Roblox uniquement — les autres plateformes n'offrent pas cet accès
  public gratuitement, le site l'indique honnêtement plutôt que d'inventer des
  chiffres.
- Favoris (onglet Résultats) : ★ sur un pseudo disponible, ou ajout manuel, pour
  le surveiller. « Vérifier maintenant » ou « Surveillance auto (5 min) » le
  revérifie et, s'il se libère, peut envoyer une alerte sur un webhook Discord
  que tu colles dans le champ prévu (Paramètres du salon > Intégrations >
  Webhooks > Nouveau webhook — ce n'est pas un lien d'invitation). La
  surveillance automatique ne fonctionne que tant que cette page reste ouverte.
- Export .txt des résultats, à côté de « Copier la liste ».
- Statistiques personnelles (onglet Résultats) : total vérifié/trouvé sur cet
  appareil uniquement — pas de compteur partagé entre tous les visiteurs du
  site, ça demanderait un vrai serveur de comptes que ce site n'a pas.

Deux choses que ce site ne peut pas faire
------------------------------------------
- Changer sa propre clé d'accès : les 10 clés sont fixes, seul l'admin peut
  réactiver/révoquer. Un vrai changement de clé par chacun demanderait un
  serveur de comptes, pas seulement une page web.
- Statistiques globales partagées par tous les visiteurs : pareil, ça
  demanderait un serveur central qui reçoit les données de tout le monde.

=== Pseudos, clés liées à un pseudo, IP et région (admin) ===
1) Cloudflare > Workers & Pages > KV > Create namespace (ex. « kr »).
2) Ton worker > Settings > Bindings > Add > KV namespace : nom de variable EXACT « KR », choisis le namespace.
3) Redéploie worker.js, puis dans le site (connecté en admin) > Admin > « Adresse du serveur » : colle l'URL du worker > Enregistrer pour tous.
4) Admin > « Créer une clé liée à un pseudo » : la clé (8 chiffres) est affichée et copiée. La personne se connecte avec CE pseudo + CETTE clé.
5) Admin > « Utilisateurs » : touche un pseudo pour voir son IP, sa région, ses connexions.
Notes : le KV gratuit est limité à 1000 écritures/jour (chaque connexion en fait 1 à 2). L'IP et la région viennent de Cloudflare (la région est approximative).
Les clés classiques (6 chiffres) marchent toujours : on y ajoute juste un pseudo libre. La clé admin (10 chiffres) n'est jamais mémorisée sur l'appareil.
